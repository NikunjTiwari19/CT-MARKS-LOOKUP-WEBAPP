# CT-Marks Web App

## 1. Problem Statement

The existing process of managing Class Test (CT) marks can be time-consuming and error-prone due to incorrect data entry, manual calculations, accidental submission, and possible data loss. Complex calculation procedures and the lack of a centralized platform can make academic record management difficult for both faculty and students. Furthermore, inadequate transparency, improper access control, and security vulnerabilities may affect the reliability and confidentiality of academic records.

Therefore, the CT-Marks Web App aims to provide a **secure, centralized, user-friendly, and role-based platform** for managing CT marks, reducing manual effort and minimizing human errors through automated calculations, validation, and controlled access.

## 2. Users and Their Roles

The system will provide different functionalities according to the user's role.

### Admin

* Manage users and their roles.
* Manage classes, subjects, semesters, and academic sessions.
* Monitor and manage system-level data.
* Control access and permissions.

### Faculty / Teacher

* Enter and manage CT marks.
* Select the relevant class, subject, semester, and assessment.
* View and update marks within authorized permissions.
* Submit marks after validation.
* View relevant student performance records.

### Student

* Securely log in to the system.
* View their CT marks subject-wise.
* View calculated totals, percentages, and grades where applicable.
* Access their academic records without being able to modify marks.

### HOD

* Monitor marks entered by faculty.
* Review relevant academic records.
* Access performance reports and summaries.
* Provide oversight according to assigned permissions.

### General Flow

The UI should minimize unnecessary navigation and provide clear feedback after important actions such as saving, updating, submitting, or viewing academic records.

## 4. User Input

The system should collect only the information required from each user.

### Admin

* Name
* User ID
* Email / Username
* Password
* Role
* Class / Section
* Subject
* Semester / Academic Session

### Faculty / Teacher

* Login credentials
* Class / Section
* Subject
* CT / Assessment
* Marks obtained by students
* Remarks *(optional)*

### Student

* Login credentials
* Subject / CT selection for viewing records

### HOD

* Login credentials
* Class / Section
* Subject
* Semester / Academic Session
* Report / Record selection

> **Note:** Student details such as name, roll number, class, and registered subjects should be retrieved automatically from the database wherever possible. Marks, totals, percentages, grades, and other calculated information should be generated by the system rather than entered manually.

## 5. Key Problems Addressed

The application is designed to address the following issues:

1. **Incorrect data entry and miscalculation** — Automated calculations and input validation reduce human errors.
2. **Accidental submission and data loss** — Confirmation mechanisms and proper data storage help protect records.
3. **Complicated interfaces** — A simple, role-specific interface improves usability.
4. **Complex formula calculations** — The system performs calculations automatically.
5. **Lack of an integrated platform** — A centralized system provides different functionalities according to user roles.
6. **Lack of transparency and biased evaluation** — Proper record management and controlled access can improve transparency and accountability.
7. **Limited use of advanced technology** — Web-based automation can modernize the CT-mark management process.
8. **Security and unauthorized access** — Authentication, authorization, and secure data management help protect academic records.

## 6. Expected Outcome

The proposed CT-Marks Web App will provide a centralized platform through which authorized faculty can efficiently manage CT marks while students can securely view their academic records. The Admin will manage system-level information and access, while the HOD will monitor and review academic records.

Automated calculations, input validation, role-based access, and minimal user input will help make the overall process **faster, more reliable, secure, and less prone to human error**.
